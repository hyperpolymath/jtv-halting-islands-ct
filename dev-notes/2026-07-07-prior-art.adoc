== JtV — prior-art / design-space analysis (2026-07-07)

Full write-up behind README §3. This was produced by a fan-out web
search → source-fetch → adversarial-verification → synthesis pass (30
primary/ secondary source blocks, 54 claim verifications; 41 confirmed
high-confidence verbatim against primary sources, 10 targeted
refutations of over-reaching sub-claims). Every quotation below was
checked against the cited primary source.

=== The question

Is JtV’s _combination_ of three mechanisms a novel point in the
language-design space, or is it already occupied?

[arabic]
. *Grammar-membership = termination certificate.* A total, addition-only
DATA sublanguage where checking totality _collapses to parsing_ — no
separate termination checker, measure, or fuel.
. *One-way structural diode.* A Turing-complete CONTROL sublanguage may
read halted DATA results; DATA can never invoke control flow. Enforced
_structurally_ — two grammars, two AST hierarchies, AST-construction
validation — not by a type system or a runtime check.
. *Injectable oracle.* A DATA block embedded in a CONTROL program is a
guaranteed-halting sub-computation the control logic may rely on.

=== Verdict

Each ingredient is individually well-precedented. The *combination*, and
above all the *enforcement modality* (purely structural: grammar + AST,
no types, no checker, no runtime guard, with the termination certificate
being grammar membership itself and the bridge genuinely one-way), has
*no clear single predecessor*. JtV is a minimalist demonstration of an
unoccupied corner, not a new capability.

=== How each neighbour actually obtains totality

The recurring finding: every established total neighbour gets totality
from a *checker or a type system*, never from grammar membership.

==== Key confirmed quotations (verbatim, primary sources)

* *Dhall* (`+dhall-lang/docs/discussions/Safety-guarantees.md+`):
_"`Dhall’s type system guarantees that if a Dhall configuration file
type checks then program evaluation/normalization will never fail.`"_
and _"`Dhall does not provide language support for recursion. If you try
to define a recursive expression or function you will get a type
error.`"_ → totality is *type-checker-mediated*, not grammar-membership.
* *Nickel* (`+nickel-lang/nickel RATIONALE.md+`): _"`All listed
languages but Jsonnet forbid general recursion, and are hence non
Turing-complete.`"_ Nickel itself keeps recursion / Turing-completeness.
* *Turner, "`Total Functional Programming`"* (SBLP/JUCS 2004): the
Security-vs-Universality dichotomy — *“we are forced to choose between
[upperalpha]
. Security … all programs are known to terminate. B) Universality …“*;
totality via three syntactic restrictions (complete case analysis,
covariant type recursion, structural recursion) plus a data/codata
split. *Not* grammar membership — a compile-time recursion-descent
criterion.
* *Blaudeau & Shankar, "`A Verified Packrat Parser Interpreter for
PEGs`"* (CPP 2020, arXiv:2001.04457): _"`In order to ensure termination
of parsing, we define a notion of a well-formed grammar.`"_ The closest
real analogue to mechanism (1) — but it certifies termination of
_parsing_, not of _evaluating the object language_.

=== Per-mechanism assessment

==== (1) Grammar-membership = termination certificate

* *Goal is old*: total, non-Turing-complete sublanguages are standard
(Turner 2004; Dhall; Starlark; CUE).
* *Mechanism is unusual*: everyone else uses a checker/type system. The
nearest "`membership ⇒ termination`" precedent is _parser_ termination
(well-formed PEGs), which is about parsing the grammar, not evaluating
the language.
* *Honest caveat* (MDPI _Mathematics_, 2023, on Turing-complete
parsing): "`membership ⇒ termination`" holds *only* for a restricted,
decidable-recognition grammar class; a Turing-powerful parser can itself
diverge. JtV’s claim is contingent on the addition-only restriction —
already stated in LIMITATIONS §2. General termination analysis is
Π⁰₂-hard, so every sound checker is incomplete; JtV sidesteps that only
by making DATA so weak there is nothing to loop on.

==== (2) One-way structural diode

* *Stage/level separation is thoroughly explored*: 2LTT/CFTT (Kovács),
MetaML/MetaOCaml (Taha & Sheard; Kiselyov), Terra (DeVito et al.),
staged λ-calculi (Feltman et al., ESOP 2016), Koka’s divergence effect.
* *Two differences isolate JtV*:
[arabic]
. Everyone enforces the split with a *type system* (universe levels,
modalities, effect rows, staging annotations) — not two disjoint
grammars validated at AST construction.
. Their bridges are *bidirectional* (`+quote+`/`+splice+`/`+lift+`) or
the *totality runs the other way* (in 2LTT the total layer is
compile-time; the runtime object layer has general recursion).
* *Terra* is closest on "`two separate AST hierarchies`" but its object
stage isn’t total and the relation is performance staging. A genuinely
one-way structural bridge _from_ a total sublanguage _into_ a
Turing-complete host appears *unoccupied*.

==== (3) Injectable guaranteed-halting oracle

* Precedented in spirit: staged PBT generators fully evaluated at
compile-time (Goldstein et al., "`Fail Faster`", 2025); Dhall’s pure
config value consumed by a host; affine type-and-effect systems where
capability-carrying terms provably cannot diverge.
* In all cases halting is *emergent* (from what’s statically known) or a
*type/effect discipline* — not structural-by-grammar. Individually JtV’s
weakest claim; really a corollary of (1)+(2).

=== Bottom line

Nothing is unprecedented in isolation. The total-vs-TC split is Turner
(2004); two-language structural separation is Terra/staging;
guaranteed-halting sub-computations appear in staged and effect-typed
settings. JtV’s only distinctive move is the *modality*: collapsing
totality-checking into parsing and enforcing a _one-way_ DATA→CONTROL
diode _purely structurally_ (grammar + AST, no types, no checker, no
runtime guard), all at once. That specific point looks empty on the map.
Whether it is worth occupying is a separate question this POC does not
try to answer.
